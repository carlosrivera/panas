# Failure evidence matrix

Status belongs to an observed run artifact. This table states what must be checked and which source can establish it; a test name is not evidence that a live two-Mac scenario occurred.

| Case                                                   | Local simulation / fixture                                  | Actual physical follow-up                                                                                | Expected accounting invariant                                                              |
| ------------------------------------------------------ | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Two providers, price/model/profile/freshness selection | Two real processes on one Mac, cloud discovery              | Run one provider on each Mac and verify both IDs/startups                                                | Discovery grants no paid work                                                              |
| Copied ticket without entitlement                      | Host authorization fixture and real MCPWire test            | Repeat from an unentitled remote buyer                                                                   | No inference or debit                                                                      |
| Expired grant, altered payload/key/startup             | Host/protocol fixtures                                      | Remote negative signed-request tests                                                                     | No unauthorized execution; never mint a terminal record from invalid proof                 |
| Duplicate purchase and run                             | Real buyer facade/cloud receipt plus accounting fixture     | Same test over cross-Mac connection                                                                      | One reservation/charge; never replay uncertain work                                        |
| Concurrent spending                                    | Two real buyer processes racing a funded cloud cap          | Repeat across buyer clients if desired                                                                   | Exactly one winner when only one quote fits                                                |
| Queue overflow / rate cap                              | Host/daemon fixtures force admission overlap                | Preconnect buyers and dispatch concurrently to one physical provider                                     | New valid rejected work has a durable failed event and zero debit                          |
| Cancel versus completion                               | Fixtures force both orderings                               | Cancel a remote bounded request; record the observed winner                                              | Provider terminal decision controls one coherent receipt                                   |
| Deadline                                               | Runtime fixture and metadata-deadline guard                 | Explicit owned runtime/network fault injection                                                           | Failure has zero debit; uncertain state holds pending reconciliation                       |
| Buyer adapter disconnect                               | Real adapter closed after dispatch, fresh adapter retrieves | Disconnect while remote generation is observed active                                                    | No automatic rerun; same receipt/debit                                                     |
| Provider crash                                         | Durable recovery/storage fixtures                           | Terminate only the owned remote provider during known active generation; restart with original state/key | Unknown remains pending; completed durable state can settle once                           |
| Sleep/wake                                             | Fixture tests wake-gap invalidation                         | Sleep Mac B until TTL expires, wake, and verify new capability tests/startup/probe                       | Stale provider cannot accept new paid work                                                 |
| Cloud service unavailable                              | Injected client failures and durable outbox fixtures        | Use an isolated controlled proxy/network block; do not stop shared Volcano services                      | New purchases fail closed, existing authorized work stays bounded, terminal outbox retries |
| Lost provider state                                    | Explicit REQUEST_NOT_FOUND/unknown path                     | Do not claim cancellation from absent state                                                              | Bounded reconciliation and audited operator decision; never fabricate completion/refund    |
| Cleanup                                                | Owned process shutdown and dedicated port checks            | Stop remote controller on its own Mac                                                                    | No leftover paid inference process; preserve ledger audit                                  |

The fixture runner reuses tests from the owning packages and labels them `component_fixture`. It does not duplicate them as purported end-to-end tests. No row becomes physical evidence from running two keys or ports on one computer.
