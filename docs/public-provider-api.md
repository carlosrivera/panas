# Public informational provider API

Anonymous read-only routes: `GET /public/providers` and `GET /public/providers/{providerId}`. Agent discovery `/providers` and `/mcp` retain their existing authentication. Provider registration, heartbeats, accounting and purchases remain authenticated. Public routes accept browser Origin with wildcard CORS for GET only and never require or return a credential.

Types are `@panas/contracts/public-registry`: publicProviderSchema/PublicProvider, publicProviderPageSchema/PublicProviderPage, publicDiscoveryQuerySchema. The projection allowlists nested fields and excludes startup IDs, peer tickets, grants, public-key enrollment records, prompts, precise device data, and buyer activity. Provider identity is a pseudonymous UUID. TEST_CREDIT_SCALE=0: one integer atomic amount is one prototype test-credit unit, not fiat or blockchain money. Format with BigInt, never floating point.

Query parameters mirror registry discovery: model, capability=text-inference, minContextTokens, minOutputTokens, maxPriceAtomic (integer string), maxLatencyMs, readyOnly, limit<=50, cursor. Public readyOnly defaults false so stale/offline entries remain informative; explicit true returns only authoritatively ready records. UUID keyset pagination is a live view, not a capacity reservation or historical snapshot.

All responses use Cache-Control:no-store. A page returns {providers,observedAt,nextCursor}; a detail response returns {provider,observedAt}. Each provider includes expiresAt (45-second heartbeat lease) and readyUntil (the earlier heartbeat or 24-hour capability-report expiry). An originally false readiness must never become true in the browser without a fresh response. An originally true readiness must become expired by readyUntil, including while the tab stays open. Anchor elapsed time to server observedAt with a monotonic client clock and conservative request elapsed time; do not rely on the visitor's wall-clock accuracy. Revalidate on visibility/focus return, refresh at the agreed 15-second cadence, and downgrade last-known results to unknown/stale during outages. Display readiness as observed metadata, not guaranteed capacity.

Failures are typed existing registry errors: 400 invalid filters/cursor, 404 unknown provider, 503 infrastructure unavailable. Never render raw exception details. The frontend can use a same-origin Next.js read proxy to this public API using a nonsecret PUBLIC_REGISTRY_URL server variable; no discovery bearer or registration credential belongs in the browser. Missing configuration must show an honest unavailable/setup state, never a live fixture.

Local validation uses the public boundary tests. Actual deployed endpoint evidence is supplied by the platform PR after bundling and deploying this registry change. This handoff extends the originally authenticated #4 read projection for the informational website in #8/#13 and #9.
